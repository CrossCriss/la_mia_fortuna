# Чеклист запуску на бойовий сервер

Статус на 2026-11-23: деплой на прод відкладено до оплати Vercel клієнткою.
Актуальні тарифи й умови сервісів перевіряти перед купівлею - тут навмисно
без цін.

## 0. Рішення до покупок

- [ ] **Чиї акаунти.** Домен, хостинг, Supabase, Monobank - оформлювати на
      клієнтку (вона власниця бізнесу) чи на розробника з подальшою передачею?
      Рекомендація: домен, хостинг і Supabase одразу на клієнтку (або її
      пошту), розробник - як співвласник/колаборатор.
- [ ] **Назва домену.** Варіанти: `.com.ua` / `.ua` / `.com`. Перевірити, що
      вільний і що збігається з Instagram `la_mia_fortuna_shoes`.
- [ ] **ФОП/реквізити клієнтки** - потрібні для бойового еквайрингу Monobank.
      Без них приймати оплату карткою не вийде, лишиться накладений платіж.

## 1. Що купити / створити

- [ ] **Домен** у реєстратора (там же налаштовується DNS).
- [ ] **Хостинг: Vercel** (Next.js 14 працює без налаштувань). Безкоштовний
      Hobby-тариф призначений для некомерційних проєктів - для магазину
      закладати платний план. Умови перевірити перед стартом.
- [ ] **Окремий production-проєкт Supabase** (не той, що для розробки).
      Безкоштовні проєкти засинають при неактивності - для магазину
      закладати платний тариф. Регіон `eu-central-1` (Frankfurt).
- [ ] **Monobank Acquiring (Plata by mono)** - бойовий токен, після
      підключення еквайрингу на ФОП клієнтки.
- [ ] **Nova Poshta API-ключ** - безкоштовно, з особистого кабінету
      (див. `CREDENTIALS.md`).
- [ ] **Telegram-бот і група клієнтки** для сповіщень про замовлення
      (див. `CREDENTIALS.md`, розділ "Telegram-бот").
- [ ] (пізніше) GA4 і Meta Pixel - безкоштовно, підключаються останніми.

## 2. Підготовка коду (розробник)

- [ ] Приватний GitHub-репозиторій і `origin`. Стан: `origin` підключено,
      CI налаштовано (`.github/workflows/ci.yml`: typecheck, lint, test).
      Перед деплоєм перевірити `git status` і зробити `git push`. Приватність репозиторію перевірити в GitHub вручну.
- [x] У `package.json` є `"postinstall": "prisma generate"` (без нього Vercel
      збере проєкт без Prisma-клієнта) і скрипт `"prisma:deploy": "prisma
      migrate deploy"`. Існуючий `prisma:migrate` - це `migrate dev`, на прод
      його запускати не можна.
- [ ] Згенерувати **нові** `ADMIN_SESSION_SECRET` і сильний `ADMIN_PASSWORD`
      для прод (не копіювати з розробки). Значення вписати тільки у Vercel.
- [x] Перевірено: `.env` є в `.gitignore` і не відстежується git. `CREDENTIALS.md`
      містить лише інструкції, без значень.
- [x] Сповіщення про **нове замовлення** реалізовані в Telegram
      (`src/lib/notify/telegram.ts`), також сповіщення про оплату. Щоб вони
      працювали, потрібні `TELEGRAM_BOT_TOKEN` і `TELEGRAM_CHAT_ID`
      (див. розділ 3 і `CREDENTIALS.md`). Без змінних сайт працює, сповіщення
      просто вимкнені.

## 3. Змінні середовища (Vercel → Settings → Environment Variables)

Production і Preview мають окремі змінні. Прод-`DATABASE_URL` у Preview не
ставити: Preview-деплої працюють з dev-БД.

| Змінна | Звідки |
| --- | --- |
| `DATABASE_URL` | Supabase prod, Transaction pooler (порт 6543): `...?pgbouncer=true&connection_limit=1`. `connection_limit=1` потрібен для serverless-функцій Vercel |
| `DIRECT_URL` | Supabase prod, Session/direct (порт 5432). Використовує Prisma для міграцій (`directUrl` у `prisma/schema.prisma`) |
| `NEXT_PUBLIC_SITE_URL` | `https://<домен>` (не localhost). Значення вшивається при збірці: після зміни потрібен Redeploy |
| `NEXT_PUBLIC_ONLINE_PAYMENT_ENABLED` | на запуску `false` (лише накладений платіж). Оплату карткою вмикаємо `true` після бойового токена Monobank. Вшивається при збірці: зміна потребує Redeploy |
| `ADMIN_SESSION_SECRET` | нова випадкова строка (32 байти hex), не коротша за 32 символи |
| `ADMIN_EMAIL` / `ADMIN_PASSWORD` | логін і пароль адмінки клієнтки. Застосовуються тільки через `npm run prisma:seed`: зміна в Vercel сама по собі пароль у БД не оновлює |
| `SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY` | Supabase prod → Settings → API |
| `PAYMENT_PROVIDER` | `MONOBANK` |
| `MONOBANK_TOKEN` | спочатку тестовий токен, потім бойовий |
| `LIQPAY_PUBLIC_KEY` / `LIQPAY_PRIVATE_KEY` | лише якщо `PAYMENT_PROVIDER=LIQPAY`; на запуску не потрібні |
| `LIQPAY_SANDBOX` | лише якщо `PAYMENT_PROVIDER=LIQPAY`; на запуску не потрібне. Для прод має бути порожнім |
| `NOVA_POSHTA_API_KEY` | кабінет Нової Пошти |
| `TELEGRAM_BOT_TOKEN` | токен бота з @BotFather (`CREDENTIALS.md`, розділ "Telegram-бот"). Не публікувати |
| `TELEGRAM_CHAT_ID` | ID Telegram-групи клієнтки, від'ємне число. Бот має бути в групі |
| `RESEND_API_KEY` / `EMAIL_FROM` | листи покупцям (Resend, `CREDENTIALS.md`, розділ 9). Задавати разом або не задавати. Порожньо - листи вимкнені, замовлення працюють. `EMAIL_FROM` - адреса на домені, підтвердженому в Resend (у продакшені не на `resend.dev`) |
| `NEXT_PUBLIC_TURNSTILE_SITE_KEY` | Cloudflare Turnstile, Site Key (`CREDENTIALS.md`, розділ 8). Порожньо - захист чекауту вимкнено. Production і Preview окремо. Вшивається при збірці: після зміни Redeploy |
| `TURNSTILE_SECRET_KEY` | Cloudflare Turnstile, Secret Key (`CREDENTIALS.md`, розділ 8). Тільки у Vercel, не публікувати. Задавати разом з `NEXT_PUBLIC_TURNSTILE_SITE_KEY` або не задавати |
| `NEXT_PUBLIC_GA4_ID` | Measurement ID виду `G-XXXXXXXXXX`. Порожньо, доки немає ID. Після зміни - Redeploy |
| `NEXT_PUBLIC_META_PIXEL_ID` | числовий ID пікселя Meta. Порожньо, доки немає ID. Після зміни - Redeploy |

## 4. Порядок запуску

1. [ ] Створити prod-проєкт Supabase, bucket `product-images` → **Public**.
2. [ ] Зробити бекап прод-БД (Supabase, план з бекапами) перед кожною міграцією.
3. [ ] Бекап (крок 2), потім накатити міграції на прод: `npm run prisma:deploy` (`prisma migrate deploy`)
      з `DIRECT_URL` прод-БД. Серед них міграція `add_checkout_antifraud` (захист чекауту). Тимчасово вказати прод-значення в `.env` або в
      змінних оточення; після роботи повернути dev-значення, `.env` не комітити.
      Не запускати `npm run prisma:migrate` (це `migrate dev`).
4. [ ] `npm run prisma:seed` проти прод-БД. Сід тільки додає відсутнє і нічого
      не видаляє. Створює: категорії (3 сезони з підкатегоріями, "Новинки",
      "Розпродаж"), розміри 36-41, 4 кольори, 3 плейсхолдер-відгуки,
      налаштування головної, адмін-акаунт з `ADMIN_EMAIL`/`ADMIN_PASSWORD`.
      Товарів не створює, їх вносить клієнтка в адмінці. Повторний запуск
      оновлює хеш пароля адміна.
      Перед сідом переконатися, що `ADMIN_EMAIL` і `ADMIN_PASSWORD` задані
      прод-значеннями: без `ADMIN_PASSWORD` сід створить адміна з паролем за
      замовчуванням.
5. [ ] Перед деплоєм: `npm run check:env -- --prod` локально з прод-змінними
      в `.env` (після перевірки повернути dev-значення, `.env` не комітити).
      Скрипт перевіряє обов'язкові змінні, `https://` і не localhost у
      `NEXT_PUBLIC_SITE_URL`, довжину `ADMIN_SESSION_SECRET`, `pgbouncer=true`
      у `DATABASE_URL`. Якщо `NEXT_PUBLIC_ONLINE_PAYMENT_ENABLED` не `false`,
      то обов'язково має бути `MONOBANK_TOKEN` (інакше скрипт завершиться з
      помилкою). Значення скрипт не виводить.
6. [ ] Створити проєкт у Vercel з GitHub-репозиторію, внести змінні з розділу 3
      (Production і Preview окремо), деплой на тимчасовий `*.vercel.app`.
      На тимчасовому URL можна тимчасово ввімкнути `NEXT_PUBLIC_ONLINE_PAYMENT_ENABLED=true`
      з тестовим токеном Monobank.
7. [ ] **Прогнати сценарій руками** на тимчасовому URL (повний список -
      `docs/acceptance.md`):
   - [ ] увійти в адмінку, додати товар із фото, розмірами й кольорами;
   - [ ] товар видно в каталозі, пошуку, на головній;
   - [ ] замовлення з накладеним платежем створюється, у Telegram з'являється
         повідомлення (якщо задані Telegram-змінні);
   - [ ] замовлення з оплатою карткою (на **тестовому** токені Monobank) →
         оплата → статус замовлення оновився;
   - [ ] автокомпліт міст/відділень Нової Пошти працює;
   - [ ] якщо задано `RESEND_API_KEY` і `EMAIL_FROM`: на тестовому замовленні покупцю приходить лист про замовлення (перевірити на свою адресу)
   - [ ] мобільна версія: кошик, чекаут, кнопки зв'язку.
8. [ ] `BASE_URL=https://<домен> npm run smoke` - має завершитися з кодом 0
      (скрипт нічого не пише в БД).
9. [ ] Перевірити прев'ю посилань (Telegram, Viber, Instagram): картка товару
      показує фото й назву.
10. [ ] Підключити домен у Vercel, прописати DNS, дочекатись HTTPS.
11. [ ] Змінити `NEXT_PUBLIC_SITE_URL` на `https://<домен>` і зробити Redeploy
        (значення вшивається при збірці).
12. [ ] Vercel Firewall: додати правило Rate Limiting для `/api/orders` і
        `/api/admin/login` (обмеження кількості запитів з однієї IP). Це основний
        захист від перебору пароля і спаму. Лічильник у коді
        (`src/lib/rate-limit.ts`) живе в пам'яті одного екземпляра функції,
        тому на Vercel він лише додатковий захист.
13. [ ] **Вебхук Monobank у кабінеті НЕ налаштовувати.** Адреса
        `/api/payments/monobank/webhook` передається в кожному рахунку
        (поле `webHookUrl`), її формує `NEXT_PUBLIC_SITE_URL`. Тому важливо, щоб
        цей URL був правильним публічним https-доменом (крок 11). Після
        тестового замовлення перевірити, що статус оплати оновився.
14. [ ] Замінити тестовий токен Monobank на бойовий (`MONOBANK_TOKEN`). Для
        запуску `NEXT_PUBLIC_ONLINE_PAYMENT_ENABLED=false` (лише накладений
        платіж). Оплату карткою вмикати, коли бойовий токен перевірено: `true`,
        Redeploy, одна реальна оплата на мінімальну суму, перевірити статус і
        сповіщення в Telegram.
15. [ ] Видалити тестові замовлення й тестові товари, внесені під час перевірки.

## 5. Контент, без якого публікувати не можна

- [ ] Реальні тексти сторінок: Про нас, Доставка, Повернення, Контакти,
      Політика конфіденційності (зараз з плашкою `PlaceholderNotice`).
      Для України бажано також публічна оферта.
- [ ] Реальна розмірна таблиця (`/size-guide`).
- [ ] Реальні відгуки (скриншоти) замість 3 плейсхолдерів.
- [ ] Нові обкладинки категорій і банер головної (поточні клієнтці не
      підходять).
- [ ] Товари клієнтка вносить сама через адмінку; перед її стартом показати
      короткий гайд (`docs/admin-guide.md`).

## 6. Після запуску

- [ ] GA4 і Meta Pixel: додати `NEXT_PUBLIC_GA4_ID` і `NEXT_PUBLIC_META_PIXEL_ID`
      (інструкція в `CREDENTIALS.md`), Redeploy. Скрипти вантажаться тільки за
      наявності ID.
- [ ] Google Search Console, перевірка sitemap/robots.
- [ ] Бекапи БД (план Supabase) і доступ до акаунтів - записати, хто за що
      відповідає.
- [ ] Відкотний план: попередній деплой у Vercel можна повернути в один клік;
      міграції БД відкочувати вручну - перед кожною міграцією на проді
      робити бекап.
