# Чеклист запуску на бойовий сервер

Статус на 2026-11-10: нічого ще не куплено й не розгорнуто, сайт працює лише
локально. Актуальні тарифи й умови сервісів перевіряти перед купівлею — тут
навмисно без цін.

## 0. Рішення до покупок

- [ ] **Чиї акаунти.** Домен, хостинг, Supabase, Monobank — оформлювати на
      клієнтку (вона власниця бізнесу) чи на розробника з подальшою передачею?
      Рекомендація: домен, хостинг і Supabase одразу на клієнтку (або її
      пошту), розробник — як співвласник/колаборатор.
- [ ] **Назва домену.** Варіанти: `.com.ua` / `.ua` / `.com`. Перевірити, що
      вільний і що збігається з Instagram `la_mia_fortuna_shoes`.
- [ ] **ФОП/реквізити клієнтки** — потрібні для бойового еквайрингу Monobank.
      Без них приймати оплату карткою не вийде, лишиться накладений платіж.

## 1. Що купити / створити

- [ ] **Домен** у реєстратора (там же налаштовується DNS).
- [ ] **Хостинг: Vercel** (Next.js 14 працює без налаштувань). Безкоштовний
      Hobby-тариф призначений для некомерційних проєктів — для магазину
      закладати платний план. Умови перевірити перед стартом.
- [ ] **Окремий production-проєкт Supabase** (не той, що для розробки).
      Безкоштовні проєкти засинають при неактивності — для магазину
      закладати платний тариф. Регіон `eu-central-1` (Frankfurt).
- [ ] **Monobank Acquiring (Plata by mono)** — бойовий токен, після
      підключення еквайрингу на ФОП клієнтки.
- [ ] **Nova Poshta API-ключ** — безкоштовно, з особистого кабінету
      (див. `CREDENTIALS.md`).
- [ ] (пізніше) GA4 і Meta Pixel — безкоштовно, підключаються останніми.

## 2. Підготовка коду (розробник)

- [ ] Створити **приватний GitHub-репозиторій**, додати `origin`, запушити
      `main`. Зараз віддаленого репозиторію немає.
- [ ] У `package.json`: `"postinstall": "prisma generate"` (інакше Vercel
      збере проєкт без Prisma-клієнта) і скрипт `"prisma:deploy": "prisma
      migrate deploy"` (існуючий `prisma:migrate` — це `migrate dev`, на
      прод його запускати не можна).
- [ ] Згенерувати **нові** `ADMIN_SESSION_SECRET` і сильний `ADMIN_PASSWORD`
      для прод (не копіювати з розробки).
- [ ] Перевірити, що в git немає `.env` та ключів (`.env` у `.gitignore`,
      `CREDENTIALS.md` містить лише інструкції).
- [ ] Вирішити, як клієнтка дізнається про **нове замовлення** (зараз тільки
      сторінка замовлень в адмінці — перевірити, чи є сповіщення; якщо ні,
      додати Telegram-бота або email).

## 3. Змінні середовища (Vercel → Settings → Environment Variables)

| Змінна | Звідки |
| --- | --- |
| `DATABASE_URL` | Supabase prod, Transaction pooler (порт 6543, `?pgbouncer=true`) |
| `DIRECT_URL` | Supabase prod, Session/direct (порт 5432) — для міграцій |
| `NEXT_PUBLIC_SITE_URL` | `https://<домен>` (не localhost) |
| `ADMIN_SESSION_SECRET` | нова випадкова строка (32 байти hex) |
| `ADMIN_EMAIL` / `ADMIN_PASSWORD` | логін і пароль адмінки клієнтки (застосовуються через `seed`) |
| `SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY` | Supabase prod → Settings → API |
| `PAYMENT_PROVIDER` | `MONOBANK` |
| `MONOBANK_TOKEN` | бойовий токен (спочатку тестовий) |
| `NOVA_POSHTA_API_KEY` | кабінет Нової Пошти |

## 4. Порядок запуску

1. [ ] Створити prod-проєкт Supabase, bucket `product-images` → **Public**.
2. [ ] Накатити міграції на прод: `prisma migrate deploy` з `DIRECT_URL` прод-БД.
3. [ ] `npm run prisma:seed` проти прод-БД — створить категорії, розміри,
      кольори, адмін-акаунт і 3 плейсхолдер-відгуки. Сід тільки додає, нічого
      не видаляє.
4. [ ] Створити проєкт у Vercel з GitHub-репозиторію, внести змінні, деплой на
      тимчасовий `*.vercel.app`.
5. [ ] **Прогнати сценарій руками** на тимчасовому URL:
   - [ ] увійти в адмінку, додати товар із фото, розмірами й кольорами;
   - [ ] товар видно в каталозі, пошуку, на головній;
   - [ ] замовлення з накладеним платежем створюється;
   - [ ] замовлення з оплатою карткою (на **тестовому** токені Monobank) →
         оплата → статус замовлення оновився;
   - [ ] автокомпліт міст/відділень Нової Пошти працює;
   - [ ] мобільна версія: кошик, чекаут, кнопки зв'язку.
6. [ ] Підключити домен у Vercel, прописати DNS, дочекатись HTTPS.
7. [ ] Змінити `NEXT_PUBLIC_SITE_URL` на фінальний домен, передеплоїти.
8. [ ] Вебхук Monobank: `https://<домен>/api/payments/monobank/webhook`
      (адреса має бути публічною — на localhost не працює).
9. [ ] Замінити тестовий токен Monobank на бойовий, зробити одну реальну
      оплату на мінімальну суму й перевірити статус.
10. [ ] Видалити тестові замовлення й демо-товари.

## 5. Контент, без якого публікувати не можна

- [ ] Реальні тексти сторінок: Про нас, Доставка, Повернення, Контакти,
      Політика конфіденційності (зараз з плашкою `PlaceholderNotice`).
      Для України бажано також публічна оферта.
- [ ] Реальна розмірна таблиця (`/size-guide`).
- [ ] Реальні відгуки (скриншоти) замість 3 плейсхолдерів.
- [ ] Нові обкладинки категорій і банер головної (поточні клієнтці не
      підходять).
- [ ] Товари клієнтка вносить сама через адмінку; перед її стартом показати
      короткий гайд (поточний гайд по адмінці застарів — оновити).

## 6. Після запуску

- [ ] GA4 і Meta Pixel (`NEXT_PUBLIC_GA4_ID`, `NEXT_PUBLIC_META_PIXEL_ID`).
- [ ] Google Search Console, перевірка sitemap/robots.
- [ ] Бекапи БД (план Supabase) і доступ до акаунтів — записати, хто за що
      відповідає.
- [ ] Відкотний план: попередній деплой у Vercel можна повернути в один клік;
      міграції БД відкочувати вручну — перед кожною міграцією на проді
      робити бекап.
