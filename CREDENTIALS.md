# Де взяти ключі для `.env`

Покрокова інструкція для кожного сервісу.

Отримані значення не надсилайте в чати й месенджери. Вписуйте їх тільки у
Vercel (Settings -> Environment Variables) і в локальний `.env`. Розробнику
достатньо повідомити, що значення внесено.

## 1. Supabase — база даних + сховище фото

1. [supabase.com](https://supabase.com) → Sign up (картка не потрібна, безкоштовного тарифу вистачить на старт).
2. New Project: назва (напр. `la-mia-fortuna`), пароль для БД — **збережи його окремо**, регіон — `eu-central-1` (Frankfurt, найближчий до України).
3. Project Settings → Database → Connection string:
   - вкладка **Transaction** (порт 6543) → це `DATABASE_URL`
   - вкладка **Session** (порт 5432) → це `DIRECT_URL`
   - в обох підстав свій пароль замість `[YOUR-PASSWORD]`
4. Project Settings → API:
   - **Project URL** → `SUPABASE_URL`
   - **service_role key** (не `anon` — саме service_role) → `SUPABASE_SERVICE_ROLE_KEY`
5. Storage → New bucket → назва `product-images` → увімкнути **Public bucket** (інакше фото не відкриються на сайті).

## 2. Monobank Acquiring (Plata by mono) — оплата карткою

Для реального прийому платежів потрібен бізнес-акаунт Monobank на ФОП клієнтки.
Щоб перевірити інтеграцію ще до цього — є безкоштовний тестовий токен:

- **Тест (можна зараз, без ФОП):** [api.monobank.ua](https://api.monobank.ua/) → кнопка "Створити тестовий токен" → `MONOBANK_TOKEN`. Гроші не списуються по-справжньому, зручно перевірити весь ланцюжок (чекаут → оплата → вебхук → статус замовлення).
- **Бойовий (коли готові приймати гроші):** застосунок Monobank для бізнесу → Plata by mono / Еквайринг → підключити онлайн-еквайринг для сайту → особистий кабінет для бізнесу → API → токен.

## 3. Nova Poshta — автокомплит відділень

1. [my.novaposhta.ua](https://my.novaposhta.ua) → увійти/зареєструватись за номером телефону (звичайний клієнтський кабінет, навіть без договору на відправлення).
2. Налаштування → API → згенерувати ключ (безкоштовно, без заявки).
3. Це `NOVA_POSHTA_API_KEY`.

## 4. (опційно) LiqPay — якщо захочете замінити Monobank

Потрібен рахунок ФОП у Приватбанку → підключення LiqPay-еквайрингу в кабінеті
ПриватБанку → `liqpay.ua` → Кабінет → Public key / Private key →
`LIQPAY_PUBLIC_KEY` / `LIQPAY_PRIVATE_KEY`, і виставити `PAYMENT_PROVIDER="LIQPAY"`
замість `MONOBANK`.

## 5. Telegram-бот (сповіщення про замовлення)

Токен бота і chat_id - чутливі значення. Токен не пересилати в чати і не
публікувати; вписувати тільки у Vercel (Environment Variables) і в локальний `.env`.

1. Telegram → знайти **@BotFather** → команда `/newbot` → назва і username бота
   (username має закінчуватися на `bot`).
2. BotFather видасть токен виду `<числа>:<літери і цифри>` → це `TELEGRAM_BOT_TOKEN`.
3. Створити **групу** для клієнтки (Telegram → Нова група) і додати в неї бота.
   Сповіщення має бачити вся команда, а не лише один особистий чат.
4. Переконатися, що бот може писати в групі: зробити його адміністратором групи
   (найпростіший варіант) або не вимикати для нього надсилання повідомлень.
5. Отримати `chat_id` групи: написати в групі будь-яке повідомлення (наприклад
   "test"), потім відкрити в браузері
   `https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/getUpdates`, підставивши
   свій токен. У відповіді знайти `"chat":{"id":-100...}` → це `TELEGRAM_CHAT_ID`.
   Число від'ємне; для груп зазвичай починається з `-100`.
   Увага: адреса містить токен, не відкривати її на чужих пристроях і в спільному
   браузері. Якщо `result` порожній, написати в групі ще раз. Якщо для бота
   налаштований webhook, `getUpdates` не покаже оновлень.
6. Записати обидві змінні у Vercel (Production) і в `.env`, зробити Redeploy.
   Перевірка: тестове замовлення → повідомлення в групі. Без змінних сайт
   працює, сповіщення просто не надходять.

## 6. GA4 (Google Analytics 4)

1. analytics.google.com → Admin (шестерня внизу зліва) → створити **Property**,
   якщо його ще немає → Data streams (Потоки даних) → Add stream → **Web**.
2. Вказати URL сайту (`https://<домен>`) і назву потоку.
3. Скопіювати **Measurement ID** виду `G-XXXXXXXXXX` → це `NEXT_PUBLIC_GA4_ID`.
4. API secret (Measurement Protocol) не потрібен, його не вписувати.
5. Записати змінну у Vercel і зробити Redeploy.

## 7. Meta Pixel (Facebook / Instagram)

1. business.facebook.com → Events Manager (Менеджер подій) → підключити джерело
   даних: Web → Meta Pixel. Створити піксель або вибрати наявний.
2. Скопіювати **числовий Pixel ID** (тільки цифри) → це `NEXT_PUBLIC_META_PIXEL_ID`.
3. Підтвердити домен магазину в Business Manager: Налаштування бізнесу → Домени
   (шлях у інтерфейсі Meta може відрізнятися) → додати домен і підтвердити через
   DNS TXT-запис або мета-тег.
4. Записати змінну у Vercel і зробити Redeploy.
   Перевірка: Meta Pixel Helper або Events Manager → Test events.

---

Найшвидший шлях перевірити все вже зараз: Supabase (5 хв, безкоштовно) +
Monobank тестовий токен (1 хв) + Nova Poshta ключ (2 хв) — жоден не потребує
реальних грошей чи документів ФОП.

## 8. Cloudflare Turnstile (захист чекауту від ботів)

Turnstile - невидима капча від Cloudflare. Без неї сайт працює, але захист від ботів вимкнено.

1. dash.cloudflare.com → Turnstile → **Add widget** (Додати віджет).
2. Назва - будь-яка, наприклад назва магазину.
3. Widget mode (режим) - **Invisible** (невидимий).
4. Domains (домени): додати бойовий домен і тимчасову адресу Vercel (`<проєкт>.vercel.app`). Без доменів віджет на сайті не спрацює.
5. Після створення відкрийте віджет. **Site Key** (публічний) → це `NEXT_PUBLIC_TURNSTILE_SITE_KEY`. **Secret Key** (секретний) → це `TURNSTILE_SECRET_KEY`.
6. Вставте обидва значення у Vercel → Settings → Environment Variables (Production і Preview). Для локальної перевірки - у `.env`. Потім зробіть Redeploy: Site Key вшивається при збірці.
7. Задайте обидва ключі або жодного. Якщо задано тільки один, `npm run check:env` покаже помилку.

Secret Key не публікувати, не вписувати в код і не надсилати в чат.

## 9. Resend (листи покупцям)

Resend надсилає покупцям лист після оформлення замовлення. Без нього сайт працює, листи просто не надходять.

1. Зареєструватися на resend.com.
2. Resend → **Domains** → **Add Domain** → ввести `fortuna-shoes.com.ua`, регіон **EU**.
3. Resend покаже DNS-записи (SPF і MX для піддомена `send`, DKIM, за бажанням DMARC). Внести їх у регістратора домена: DNS домена керується там (NS `uadns.com`). Записи вносить власниця домена або людина з її доступом.
4. Дочекатися статусу **Verified** у Resend. Поки статус не Verified, листи не відправляються.
5. Resend → **API Keys** → **Create API Key**. Права - тільки **Sending access**, домен - `fortuna-shoes.com.ua`.
6. Вставити у Vercel → Settings → Environment Variables (Production і Preview):
   - `RESEND_API_KEY` - ключ із пункту 5;
   - `EMAIL_FROM` - адреса відправника на підтвердженому домені, наприклад `La Mia Fortuna Shoes <orders@fortuna-shoes.com.ua>`.
   Потім зробіть Redeploy.
7. Задайте обидві змінні разом або жодну. Якщо задано тільки одну, `npm run check:env` покаже помилку.

Ліміти безкоштовного тарифу: 100 листів на день, 3000 на місяць.
Відповіді покупців приходять на пошту клієнтки (`SITE.seller.email`).

Ключ `RESEND_API_KEY` не публікувати, не вписувати в код і не надсилати в чат.
